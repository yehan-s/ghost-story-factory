# 2026-05-09 VN 演出意图契约 Pass 7

## 1. 任务描述

继续推进正式剧本的 VN / galgame 目标。当前正式树已有 `presentation`,但大量关键节点仍缺少镜头、CG 意图、转场意图。目标是在不新增真实素材、不改运行时的前提下,先把演出契约写进数据和审计。

## 2. Chief Editor — 首席编辑

- 相关度:深度参与
- 意见:值得做。现在文本已经开始响应玩家行为,但关键场景缺少演出层语义,会导致未来图形化客户端只能猜作者意图。
- 产出:优先补遗失档案、红色电话亭、B3、清晨湖滨、红衣女孩、8 棺自己和主结局。

## 3. State Architect — 状态系统建筑师

- 相关度:普通审查
- 意见:演出意图不应新增 gameplay flag。`camera / cg_intent / transition_intent` 是静态数据,不进入玩家状态。
- 产出:禁止新增 route / oneshot / arc 状态;只补 presentation。

## 4. Meta-Game Designer — 元游戏设计师

- 相关度:普通审查
- 意见:CG 意图字段是未来 CG / 结局收集本的前置结构。现在不接收集本,但命名应稳定。
- 产出:`cg_intent` 使用可长期保留的语义 ID,不要写临时描述句。

## 5. UX Designer — 文字体验设计师

- 相关度:深度参与
- 意见:文字过渡和画面不是装饰。每个关键节点要明确玩家“看到什么角度”和“为什么这样转场”。
- 产出:字段至少覆盖 `camera`、`cg_intent`、`transition_intent`。

## 6. Lore Keeper — 世界观考据师

- 相关度:普通审查
- 意见:演出意图必须服务杭州夜班质感,避免通用恐怖词汇。镜头应围绕档案、老电话、电视墙、湖滨、货梯、工牌。
- 产出:不新增世界观元素,只提炼已有文本中的画面。

## 7. Topology Designer — 拓扑设计师

- 相关度:深度参与
- 意见:不要一次性要求 145 节点全补意图,否则会变成字段填表。先定义“关键节点名单”,审计只盯这批节点。
- 产出:审计检查关键节点缺字段时 warning,正式树必须无该 warning。

## 8. QA / Path Tester — 路径测试官

- 相关度:深度参与
- 意见:必须加测试证明审计能抓缺失,并确认正式树不报警。改 fragment 后重建 `tree.json`,跑 `audit_all` 和统一测试。
