## § 1. 任务描述

**用户原话**:"先启动团队,然后沙盒方向第一个真实任务"

**助手转述**:这是个**元任务** — 让 7 人评审团从所有可能的入手点中,推荐 1 个最合理的"沙盒方向第一个该动手的真实开发任务"。第一个任务必须满足:单一聚焦 / 1-2 周可完成 / 高杠杆(撬动后续) / 验收标准明确。

**项目目标**:把现有「杭州夜班保安」v7 剧本(109 节点 / 13 NPC / 8 主结局 / 41 种结局体验)做成开放沙盒,体验对标 galgame + 超越小说阅读,核心维度为「状态密集叙事 + 元游戏」。

**任务影响范围**:多层(剧本 + 引擎 + UX),核心是引擎 + 数据层。

## § 2. Chief Editor — 首席编辑

**相关度**:深度参与
**层级判定**:多层(剧本 + 引擎 + UX),核心是引擎与剧本数据层
**初步倾向**:节点状态审计 + 玩家知识图谱(PKG)MVP

**意见**:

从连续性审查角度看,真正卡住所有后续工作的根本问题,是项目缺少一份"事实清单 + 状态契约" — 109 个节点里哪些已有 narrative_variants、变体覆盖了哪些状态轴、哪些 NPC 真的会因玩家"知道了什么"而改话。沙盒方向所有体验承诺(状态密集、知识继承、好感度、CG 收集)都建立在"我们清楚每个节点的状态分化能力"之上。

更关键的连续性风险是 **伏笔-兑现链尚未被状态化**。`PROJECT-STATE-AND-FORESHADOW-REGISTRY.md` 已注册 13 NPC 的伏笔,但"玩家是否知道"目前没有作为可被 variants 引用的状态。

**初步候选**:节点状态审计 + 玩家知识图谱(PKG)MVP — `tools/audit_variants.py` 导出 109 节点 variants 覆盖矩阵 + State 加 `knowledge: Set[str]` 字段 + effects.learn 动作 + 选 `n_npc_predecessor_voice` 做"知识门控"试点。

## § 3. State Architect — 状态系统建筑师

**相关度**:深度参与
**第一步候选**:`tools/audit_state.py` 状态字段使用矩阵审计 — 不动代码,先把现有 200+ flags / 30 道具 / 13 NPC 的 variants 覆盖率和死字段曝光出来。
**对 PKG 方案的表态**:**反对**(暂时)

**核心论据**:
1. `knowledge: Set[str]` 在语义上和现有 `flags: Dict[str,bool]` 是同一种东西 — 两套机制做一件事
2. effects 的 `learn` 完全可以是 `flags: {knowledge.linmou_other26: true}` 命名规范约束,**根本不需要引擎扩展**
3. `meets()` 已支持嵌套 `any_of/all_of/not` 和按键判 flags,`knowledge_has`/`knowledge_lacks` 是冗余 API
4. 真问题不是"缺一个字段",是"现有 200+ flags 没有命名规范、没人知道哪些是死的"

**反加法者意见 — 现在代码里该砍/合并的字段**:
1. `route: Optional[str]` — v7 已废弃但代码未清理。**砍**
2. `skipped_landmarks: List[str]` 与 `shifts_skipped: int` 计数语义重叠。**合并**
3. 15 件"flag-driven 装饰道具"(14 寸黑白电视 / 1959-043 粮票 / 1987 录像带 / ...)— 拿到时进 inv + 同时 set flag,后续 require 全走 flag,inv 那一份是纯展示。**统一规则,二选一**

**验收 checklist 关键 3 项**:
1. 产出 `tools/audit_state.py`,输出 109 节点 × 现有 State 字段(flags/inv/visit_counts/last_landmark/route/meta_flags)的引用矩阵
2. 死字段清单可执行删除 — 至少标记 5 个以上"只 set 不 require"或"只 require 不 set"的 flag/inv 道具
3. 报告必须显式回答:`n_npc_predecessor_voice` 用 `visit_count_min + flags + any_of` 能不能实现"知识门控"?能则 PKG 当前不批

## § 4. Meta-Game Designer — 元游戏设计师

**相关度**:深度参与
**第一步候选**:**结局收集本(CG-Codex)v0** — `endings_seen` / `stories_completed` / `ENDING_UNLOCKS` 数据已落盘,8 主结局 + 41 体验缺一个"已收/未收"的可视化终点
**对 PKG 方案的表态**:**部分同意**

**核心论据**:
- PKG 改的是 player state schema 与所有 tree 节点 effects 字段,触面横切,**1-2 周内只能交付"框架 + 1 NPC 试点",玩家感知为零**
- PKG 的价值兑现链是"知识图谱 → 跨周目继承 → 解锁更深选项",而**继承端的存档基础设施(SaveManager v3 + ENDING_UNLOCKS)已经就位**,真正缺的是"玩家能看到自己积累了什么"
- CG 收集本是 PKG 的**前置 UI 验证器**:先证明"玩家看到收集进度会想再玩",再决定是否值得为 knowledge 图谱多花 2 周

**周目/CG/好感度优先级**:**CG 第一 → 周目深化 → 好感度(慎做或不做)**

- **CG 第一**:数据已就绪,缺渲染层,1 周内可交付,直接产生重玩驱动力
- **周目第二**:依赖 CG 验证的玩家行为数据来定义粒度
- **好感度最后甚至砍掉**:13 NPC 中 9 个是恐怖对象/亡者/鬼魂,对它们做"好感度 +1"是世界观破坏

**验收 checklist 关键 3 项**:
1. 完成度面板可在主菜单一键打开:`X/8 主结局 · Y/41 体验 · Z/9 角色棺解锁`
2. 每个已解锁结局可回看:narrative 文本 + 触达条件提示,**零新字段**
3. 关卡内首次达成有 `[档案+1] E_TRUTH 揭穿真相` 提示,挂渲染钩子即可

## § 5. UX Designer — 文字体验设计师

**相关度**:深度参与
**第一步候选**:`effects.learn` + 1 行级"知道了 X"瞬时反馈条 — 复用现有"档案 +1"卡片渲染器,零新组件
**对 PKG 方案的表态**:**部分同意**(同意 learn effect 但反对"零 UI 反馈")

**核心论据**:
- 引擎层加 `learn` 但屏幕零反馈 = 玩家盲操作,体验上是负收益
- galgame 的"察觉感"必须**当帧反馈**
- 复用 `_render_apply_events_tui`(已有 `inv_add` / `puzzle_add` / `landmark_visited` 语法),加 `knowledge_learn` 事件几乎是 1:1 复制
- 不破坏现有玩法:`learn` 是新 effect,旧节点没有,完全向后兼容

**TUI 草图**:

**验收 checklist 关键 3 项**:

## § 7. Topology Designer — 拓扑设计师

**相关度**:深度参与
**第一步候选**:**Flag 降级清扫(Flag Demotion Pass)** — 把 234 个 flags 中那 153 个"一次性 flag"就地降级为 `visit_count` / `narrative_variants` / `_foreshadow_slot`
**对 PKG 方案的表态**:**反对(至少要求暂缓)**
**对"加 knowledge 维度"的判决**:**降级**(不接受新增 `State.knowledge` 字段)

**核心论据(数据驱动)**:
- **234 flags 中 153 个只用一次(65%)** — 状态空间爆炸明证
- 现有 234 flags 中 153 个一次性 flag,实质上已经在用 flags 模拟"知识"
- `flags["claimed_linmou"]` / `flags["seven_returned"]` / `flags["linked_to_eight_self"]` 已经是知识 flag,只是名字没规范
- 项目已有**三个表达知识的通道**(flags / inv signaling / `_foreshadow_slot`)— 在加第四个之前,先把前三个合并到一个

**反加法者审计**:
1. **`s{1-7}_*` 前缀的局部 flag(60+ 个)** — 等价于 `visit_counts[node] > 0` + 该节点 `_foreshadow_slot`。**砍 — 下沉到节点局部**
2. **`*_revisit_*` 系列(6 个,引用 11-14 次)** — 已被 `visit_counts[node_id] >= 2` 完全覆盖。**合并**
3. **`inv` 中 signaling-only 道具**(1987 告示残页 / 7 工人速写 / 武林门 7 人录音)— 用 inv 模拟知识。**合并到统一通道**

**降级方案**(替代 PKG):
- "玩家知道 X" → `_foreshadow_slot: ["X"]`(已存在,被 `save_manager.mark_foreshadow_seen` 跟踪)
- "玩家在 N 节点过/重访过" → `visit_counts[node_id] >= N`(已存在)
- `meets()` 的 knowledge 表达 → 直接用 flags 命名空间约定如 `flags: {"k.linmou_truth": true}`,**不新增字段、不新增 require 关键字**

**验收 checklist 关键 3 项**:
1. `tree.json` 全局 flags 唯一键数从 **234 降到 ≤ 80**(只保留被 ≥2 节点引用的"真·全局")
2. `tools/path_explorer.py` 跑过的全部既有路径 → 8 个主结局 + 41 种结局体验**全部仍可达**
3. State 类与 `meets()` 的 `flags` 分支**保持签名不变**,新内容全部走 `visit_counts` + `_foreshadow_slot`(零引擎扩展验收)
