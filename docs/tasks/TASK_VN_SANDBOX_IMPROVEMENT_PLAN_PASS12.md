## 0. 方案判断

当前项目已经跨过“能跑、可达、可审计”的底线,但还没有达到用户目标里的 galgame / 视觉小说厚度。真正缺口不是继续堆节点数量,而是把“开放沙盒”做成玩家能感到自己在改变故事的系统。

【核心判断】
✅ 值得做:这是产品体验主线,不是美化工程。

【关键洞察】
- 数据结构:正式树已有 `effects / narrative_variants / presentation / foreshadows / deductions / endings / save_manager`。下一阶段应先复用这些结构,不要急着新增 schema。
- 复杂度:把大目标拆成 5 条可验证链路:剧本密度、选择反馈、周目记忆、VN 演出、质量红线。
- 风险点:最容易写烂的是“加字数”。字数不是深度。玩家可感知的因果、角色回应和路线回收才是深度。

---

## 1. 当前缺口

### 1.1 剧本层

- 普通地标仍有一批节点像“地点说明”,互动后回收不足;
- 赵某的主角弧线已经有身份回收,但内心变化还不够连续;
- 林某 1985 线可玩,但与 G-273 主线的互相照见仍可继续加强;
- 叶某、红衣女孩、巡夜员群像已有可读进展,但终局前的联动还不够集中。

### 1.2 玩法层

- Pass 11 已让选择意图可见,但选择后的“本轮行为画像”还没有形成一个稳定的中途 UI;
- 玩家知道自己做了选择,但不总能马上感到“系统记住了我”;
- 地图 hub 仍偏功能入口,需要更像“路线账本”和“现场调度台”。

### 1.3 VN 演出层

- Pass 10 已把 `presentation` 接进运行时,但仍是文本 fallback;
- 缺少场景级节奏约定:何时短镜头、何时长段落、何时用演出提示替代大段解释;
- 缺少“结局前 CG / 立绘 / 音效优先级清单”,未来做资产时会乱。

### 1.4 周目反馈层

- 已有 ending / foreshadow / deduction 持久化基础;
- 但玩家完成一轮后,缺少“本轮路线复盘”和“下一轮能带走什么”的强提示;
- gallery / archive / ending review 还没有形成 VN 常见的收集驱动力。

### 1.5 工具红线层

- 现有 `audit_all` 能保证可达和契约,但不够判断“玩家体验是否有反馈”;
- 缺少对选择提示覆盖率、结局复盘覆盖率、关键 NPC 终局回收的审计;
- 文档中的节点数基线有历史漂移,需要以工具输出为准刷新。

---

## 2. 总体改进原则

1. 先修体验链路,再加内容规模;
2. 先复用现有状态,再考虑新 schema;
3. 选择前给意图,选择后给反馈,结局后给复盘;
4. 每个大节点至少承担一种功能:推进、揭示、回收、反咬、解锁;
5. 不把开放沙盒改成线性章节;
6. 不把 VN 体验做成数值优化表;
7. 所有正式剧本改动必须同步 Task / Issue / 团队评审 / audit / 测试。

## 3. 分阶段方案

### P0: 基线清账与指标刷新

目标:
- 把 roadmap 里的历史数字刷新为当前正式树基线;
- 明确哪些任务已完成,哪些只是规划;
- 避免后续继续引用 `145/145` 这类旧数据。

交付:
- 更新 `TASK_NEXT_VN_SANDBOX_GOALS.md`;
- 在方案文档里记录当前基线:
  - 节点:160;
  - 可达:160/160;
  - 结局:21;
  - 演出节点:160/160;
  - 演出意图节点:32;
  - variants:327;
- 若工具输出变化,以 `bash tools/audit_all.sh` 为准。

验收:
- 文档基线与审计输出一致;
- 无代码改动时只跑 `git diff --check`。

### P1: 选择后反馈闭环

目标:
- 在玩家做选择后,用短反馈告诉他“这次行为被系统记住了”;
- 形成稳定的本轮行为画像输出,但不暴露完整数值。

建议实现:
- 复用 `State._last_events`;
- 将 `choice_affordance_tags` 和 `_render_apply_events` 对齐;
- 新增“路线账本”轻量渲染:
  - 取证倾向;
  - 曝光倾向;
  - 救人倾向;
  - 绕开 / 漏卡倾向;
  - 审判 / 删除倾向。

优先节点:
- `n_landmark_picker`;
- `n_scene_b3_corridor`;
- `n_scene_evaluator_room`;
- `n_scene_morning_lakeside`;
- 核心结局节点。

验收:
- 至少 4 类行为画像能在中途或终局前被看见;
- 不新增 DB schema;
- 新增测试覆盖反馈 formatter。

### P2: 角色关系账本深化

目标:
- 让关键 NPC 不只是“被玩家访问”,而是持续读取玩家行为;
- 把关系反馈集中到终局前,形成 VN 式情绪爆点。

优先角色:
- 红衣女孩:从“被救”推进到“自己选择走向 27 楼”;
- 叶某:从琴房受害者推进到“教会红衣女孩不等大人”;
- 7 名巡夜员:从背景编号推进到“不同失败方式的群像账本”;
- 清洁工:从功能 NPC 推进到“删除痕迹的反面审判者”;
- 评价室:从结局入口推进到“本轮行为法庭”。

建议实现:
- 每批只改 3-5 个节点,避免大规模文本污染;
- 每批至少新增或增强 2 个 `narrative_variants`;
- 每批必须有一个终局前回收点。

验收:
- `audit_variants` 仍无 `undifferentiated_revisit_nodes`;
- `audit_script_depth` 通过;
- 至少 3 个 NPC 在终局前读取玩家行为画像。

### P3: 周目复盘与收集驱动

目标:
- 一轮结束后,玩家知道自己解锁了什么、漏了什么、下一轮为什么值得重来;
- 把 VN 常见的 ending / archive / gallery 驱动力接到现有持久化层。

建议实现:
- 结局页增加路线复盘:
  - 本轮主要倾向;
  - 已解伏笔;
  - 新增结局;
  - 下一轮可追的未解档案;
- 档案视图增加“未解提示”,但不剧透答案;
- 结局记录显示“本轮关键行为标签”。

验收:
- 任意结局后可看到本轮复盘;
- 不启动完整 Textual app 的 formatter 测试覆盖复盘文本;
- save 文件兼容旧数据。

### P4: VN 演出节奏升级

目标:
- 让 `presentation` 不只是显示资产 label,而是指导文字节奏;
- 建立未来真实素材生产的优先级。

建议实现:
- 增加 `tools/audit_presentation_priority.py` 或扩展 `audit_script_depth`;
- 标记高优先级演出节点:
  - 首次进入 S1;
  - 红衣女孩关键抉择;
  - B3 走廊;
  - 评价室;
  - 晨湖;
  - True / Truth / Data / Hidden / Broadcast 结局;
- 为关键节点记录:
  - 立绘候选;
  - CG 候选;
  - 音效候选;
  - 转场节奏。

验收:
- 关键演出节点不少于 40;
- 每个核心结局都有 `camera / cg_intent / transition_intent`;
- CLI/TUI fallback 不变。

### P5: 质量红线升级

目标:
- 把“深度不够”转成机器可守的指标;
- 防止后续开发把体验打回菜单树。

建议新增审计:
- `audit_choice_feedback.py`:
  - 有 effects 的选择是否能产出至少 1 个非剧透标签;
  - 锁定选项是否不泄露收益标签;
- `audit_route_payoff.py`:
  - 关键行为 flag 是否至少被 1 个终局前节点读取;
  - 关键 NPC 是否至少有 2 个行为画像回收点;
- `audit_ending_recap.py`:
  - 结局是否存在路线复盘信息;
  - 周目持久化是否被展示。

验收:
- 新审计挂入 `tools/audit_all.sh`;
- 新审计有单元测试;
- 完整测试通过。

## 4. 推荐执行顺序

1. P0: 文档基线清账;
2. P1: 选择后反馈闭环;
3. P2: 角色关系账本深化第一批;
4. P3: 结局复盘与周目收集;
5. P4: 演出优先级与素材路线;
6. P5: 质量红线升级。

理由:先让玩家“看见系统记住了我”,再让角色和结局集中回收。否则继续加戏,玩家仍然会觉得自己只是在读分叉文本。
